# Setting Up Your Replit Designathon Canvas for Judges

Here's a full walkthrough of what you need to do to your canvas so judges can evaluate your project quickly and effectively.

---

## 1. Organize Your Canvas with Clear Sections

Structure the canvas so a judge can scan it in under 2 minutes:

- **Header / Title block** — Project name, your name/team, and a one-line description.
- **Problem & Solution** — A brief framing of what problem you're solving and your design approach.
- **User Flow / Journey** — Show the key screens in order, connected by arrows, so judges understand the intended experience.
- **Key Screens / Frames** — Your primary UI mockups, clearly labeled (e.g., "Home", "Onboarding", "Dashboard").
- **Design System Snapshot** — Colors, typography, and component samples in one area.
- **Notes / Annotations** — Callouts on important decisions (why you chose a layout, a color, an interaction pattern).

---

## 2. Name and Label Everything

- Give every frame/artboard a clear, descriptive name (not "Frame 14").
- Use section labels or sticky notes to group related screens.
- Label interactive flows with numbered steps if there are multiple user paths.

---

## 3. Set a Proper Starting View / Prototype Entry Point

- If your tool supports prototyping (Figma, Framer, etc.), set the **starting frame** to the first screen of your main flow.
- Make sure the prototype link opens to the right starting point — not a random artboard.
- Test the prototype link yourself before submitting.

---

## 4. Make the Canvas Public / Shareable

- Set sharing permissions to **"Anyone with the link can view"** (or comment, if you want feedback).
- Copy the share link and verify it works in an incognito/private browser window.
- If submitting to a Replit-hosted canvas (`/__mockup`), confirm the preview URL is publicly accessible.

---

## 5. Clean Up the Canvas

Remove anything that would confuse or slow down a judge:

- Delete unused frames, old explorations, or scratch work (or move them to a separate "Archive" page/section).
- Align and evenly space frames — a messy canvas signals careless work.
- Zoom out so the full canvas is visible at a glance when the link is opened.

---

## 6. Add a "Read Me First" Frame

Place a prominent frame at the top-left (where most tools open by default) with:

- **Project name and tagline**
- **How to navigate the canvas** (e.g., "Start here → follow arrows → see design system on the right")
- **Prototype link** (if separate from the canvas link)
- **Your contact info** (optional but helpful)

---

## 7. Check Fonts, Images, and Assets

- Ensure all fonts are embedded or use web-safe/Google Fonts so they render for judges without your local fonts.
- All images should be embedded, not linked from external sources that may break.
- Icons should be vector-based, not blurry rasters.

---

## 8. Prepare Your Submission Package

For a Designathon, judges often need more than just the canvas:

- **Canvas/design file link** — the primary artifact.
- **Live prototype link** — clickable walkthrough.
- **Short video walkthrough** (1–2 min) — narrate the key flow; judges love this for async review.
- **Slide deck** — executive summary of problem, solution, and design decisions.

Based on your project setup, you already have a canvas, video, slide deck, and web artifact — make sure all four links are included in your submission form.

---

## 9. Final Checklist Before Submitting

- [ ] Canvas is publicly accessible (test in incognito)
- [ ] Frames are named and organized
- [ ] Prototype starts at the correct frame
- [ ] "Read Me First" frame is present
- [ ] All fonts/images render correctly
- [ ] No stray or unfinished frames cluttering the canvas
- [ ] Video, slides, and live site links are all working
- [ ] Submission form is filled out completely

---

Good luck with your Designathon submission! 🎉
